## What was broken, and what shipped

### 1. $9,481.40 of streaming revenue was hidden (fixed)
`symphonic_statement_periods` was a hollow shell: 77 rows, every financial and
date column NULL. `/dashboard/money` sums `total_earnings_after_fees` off that
table, so the "Recorded music" tile read **$534** (VMG only) while $9,481.40 of
Symphonic royalty sat untouched in `symphonic_royalty_lines`.

Migration `094` backfills it from the line items, with a reconciliation guard that
aborts on any mismatch. It caught a real 3-cent rounding drift on first run.

Tile now reads **$10,015.26**. Verified to the cent.

Also: the "latest period = September 2025" figure was a text-sort artifact of the
month-name column. Real latest period is **February 2026**.

### 2. Analytics was fabricated (fixed)
`/dashboard/analytics` was a hardcoded `ARTIST_METRICS` object, and `getMetrics()`
fell back to DirtySnatcha for **every artist**. Dark Matter's page showed Leigh
Bray's listener counts and Detroit as their top city.

It claimed DirtySnatcha had 4,500 Spotify followers. The live snapshot says
**27,871** — off by 6x. It invented per-track stream counts that the Spotify API
does not expose at all.

This violated the repo's own guardrail: *never fabricate metrics*.

Rewritten to read `spotify_daily_snapshots` + `artist_audience_geo`, with a 30-day
trend, and an explicit "—" plus the reason wherever no source exists.

### 3. Spotify page said "not connected" for everyone (fixed)
It read `artists.social_stats.spotify`, populated only by a manual Refresh button.
**0 of 8** artists had it set — while the nightly cron had been quietly storing
snapshots for five of them for months. Now hydrates from the snapshot table.

### 4. The dashboard root showed a fabricated number (fixed)
"89 tracks not registered" was computed by subtracting a **label-wide** BMI count
(35, essentially none of them hers) from Leigh Bray's 124-track catalog. Both
sides now scope to the same artist.

Real numbers for Leigh Bray: 124 released tracks, 82 BMI-registered, **0 MLC**,
**0 SoundExchange**. The MLC gap is the actual unclaimed-royalty leak and now
leads as a red attention item.

### 5. DAD was taking money for software that does not exist (disabled, your call)
`/api/dad-checkout` returned a live PayPal `_xclick-subscriptions` URL at
**$19.00/month recurring**, effective immediately.

- No DAD backend exists — no scan, classifier, or orchestrator route
- It **ignored the `tier` argument** while the page advertised $39 / $69
- It carried **no trial parameters** behind a "Start 14-Day Free Trial" CTA

Billing disabled at the API, so even a stale cached bundle cannot reach PayPal.

### 6. DAD has been losing every signup since 2026-07-03 (fixed)
Found by probing production after the above. Two stacked bugs:

- `.upsert(...).catch(fn)` — `PostgrestBuilder` has no `.catch()`, so the call
  threw `TypeError` and the route 500'd on every request
- both routes wrote to `dad_waitlist`, a table **dropped** by migration
  `mailing_list_replaces_dad_waitlist` on 2026-07-03

Every DAD signup, paid and free, has 500'd and been lost for six days.
`mailing_list_subscribers` had 0 rows, consistent with that.

**Silver lining:** because the paid route threw *before* returning a PayPal URL,
the checkout could never actually charge anyone. The billing exposure was latent,
not realized. No one was charged.

### 7. `web-push` was missing from the lockfile (fixed)
Declared in `package.json`, absent from `package-lock.json`. Every local build and
any `npm ci` failed. Vercel only survived by falling back to `npm install`.

### 8. Channel monetization eligibility (built)
The one genuine build gap. `artist_monetization_targets` existed with a reader and
**zero writers**. `youtube-analytics.ts` was dead code wired to the *Gmail* OAuth
client instead of the artist YouTube token.

Built: migration `095` (unique key for idempotent upsert), an eligibility writer
against the real YPP rule (1,000 subs AND (4,000 watch-hours/12mo OR 10M
Shorts-views/90d)), the cron wiring, and `/dashboard/monetization` + nav.

**0 of 8 artists have connected a channel**, so the page renders its "not
connected" empty state. That is the correct output — a metric we cannot fetch is
shown as no data, never as a zero.
